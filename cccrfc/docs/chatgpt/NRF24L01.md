# How do I use a pair of NRF24L01 transceivers to transfer files between Linux devices?

Transferring files between two Linux machines using nRF24L01 modules isn’t as straightforward as using a standard network interface (like Ethernet or Wi-Fi), because the nRF24L01 does not present itself as a typical “network card.” Instead, it is a low-level 2.4 GHz radio transceiver accessible over SPI. As a result, you need to build or use a custom communication protocol and handle the packetizing, sending, receiving, and error checking yourself (or use an existing library that does it for you).

Below is a high-level overview of how you can set this up:

---

## 1. Hardware Setup

1. **Wiring the nRF24L01**  
   Each nRF24L01 module will connect via SPI to its host Linux device (e.g., Raspberry Pi or another SBC). You need at least these signals:
   - VCC (3.3 V) – Make sure to power from a stable 3.3 V source (5 V will damage the module).
   - GND
   - CE (Chip Enable)
   - CSN (Chip Select for SPI)
   - SCK (SPI clock)
   - MOSI (SPI master out, slave in)
   - MISO (SPI master in, slave out)

2. **Check Operating Voltage**  
   nRF24L01 modules must be powered at 3.3 V and **not** 5 V. If your host device runs at 5 V on its SPI pins, you’ll need a level shifter or a 3.3 V SPI interface.

3. **Antenna and Range Considerations**  
   Basic nRF24L01 modules have a small PCB antenna and short range (~10–20 m line of sight). The PA/LNA versions with an external antenna can extend range significantly.

---

## 2. Software Setup on Linux

### Option A: Using the TMRh20 “RF24” Library

The [TMRh20 RF24](https://github.com/nRF24/RF24) library supports not only Arduino but also Raspberry Pi and other Linux devices via `spidev`. It provides a C++ API to configure and send/receive packets.

1. **Install Dependencies**  
   Make sure you have `git`, `cmake`, and your distribution’s development tools installed (e.g., `build-essential` on Debian/Ubuntu).

   ```bash
   sudo apt-get update
   sudo apt-get install git cmake build-essential
   ```

2. **Clone and Build**  

   ```bash
   git clone https://github.com/nRF24/RF24.git
   cd RF24
   mkdir build && cd build
   cmake ..
   make
   sudo make install
   sudo ldconfig
   ```

3. **Wiring Setup in Code**  
   By default, the library expects:
   - `CE` on GPIO22 (physical pin 15 on a Raspberry Pi)
   - `CSN` on SPI CE0  
   You can override pins in the constructor if needed.

4. **Test with Example Code**  
   The `RF24/examples_linux` directory has sample code (e.g., `gettingStarted_call_response.cpp`). Run it on both devices to confirm basic communication.

5. **Implement File Transfer**  
   Since nRF24L01 packets are limited to 32 bytes, you must:
   - Read your file in small chunks (e.g., 32 bytes).
   - Send each chunk via the RF24 library.
   - Implement a small “protocol” that:
     - Tells the receiver how many bytes to expect,
     - Handles timeouts or retries,
     - Confirms the last packet was received,
     - Writes the chunks out to a file on the receiving end.

   A simple approach:
   - Sender sends a short header (filename, file size, etc.).
   - Receiver reads and prepares for `N` bytes total.
   - Sender chunks the file into 32-byte frames, sends each, waits for an ACK from the receiver before sending the next chunk.
   - Receiver writes each chunk to the output file.
   - Once complete, the receiver responds with a success message.

### Option B: Using Python Libraries

There are Python wrappers for the same TMRh20 RF24 library, often called `pyRF24` or `pyNRF24`, which can be simpler for quick scripting. The setup is similar—both devices must run matching Python scripts that chunk the data and manage sending/receiving.

For example:

1. **Install `spidev`**  

   ```bash
   sudo apt-get install python3-pip python3-spidev
   pip3 install pyRF24
   ```

2. **Use `pyRF24`**  

   ```python
   from RF24 import RF24, RPiHardwareSpi

   # Example initialization
   radio = RF24(22, 0)  # CE on GPIO22, CSN on CE0 SPI

   # Configure radio addresses, channels, data rate, etc.
   # radio.openWritingPipe(0xF0F0F0F0D2)
   # radio.openReadingPipe(1, 0xF0F0F0F0E1)
   # ...
   ```

Then implement the same type of file-sending logic as in C++.

---

## 3. Consider Higher-Level Protocols

**RF24Network**, **RF24Mesh**, and **RF24Ethernet** are extensions of the TMRh20 library that offer a more structured network-like abstraction over nRF24L01. They can help if you want to do more than just send raw data frames:

- **RF24Network** provides a lightweight packet-based network layer for nRF24 modules.
- **RF24Mesh** builds a dynamic mesh on top of RF24Network.
- **RF24Ethernet** attempts to present an Ethernet-like interface to the user code, but it’s primarily used in microcontroller contexts. It is not a plug-and-play Linux network interface in the normal sense.

If you only want file transfer between two devices (point-to-point), sticking to the core RF24 library is typically simpler.

---

## 4. Putting It All Together (Example Workflow)

Let’s outline a minimal solution using the C++ TMRh20 library:

1. **On Device A (Sender)**  
   1. Initialize the nRF24L01 via the RF24 library.  
   2. Open a writing pipe to an agreed-upon address (e.g. `0xF0F0F0F0AA`).  
   3. Take a filename as input, open it, and read in 32-byte chunks.  
   4. For each chunk:
      - Transmit the chunk.
      - Wait for an acknowledgement from the receiver (can be a simple 1-byte response saying “OK”).
   5. After sending the last chunk, send a “done” message.

2. **On Device B (Receiver)**  
   1. Initialize the nRF24L01 via the RF24 library.  
   2. Open a reading pipe that matches the sender’s address.  
   3. Listen for incoming data.  
   4. On receiving the file header (size, name, etc.), create or open an output file.  
   5. Keep reading chunks until you receive the “done” signal.  
   6. Respond with a small acknowledgement after each chunk, so the sender knows it can send the next.  
   7. Close the file when complete.

Because the raw packet size is limited, you do need to handle chunking, retries, and acknowledgments yourself (or using library features like auto-ack and dynamic payloads). While this takes some work, it gives you fine-grained control over the data flow.

---

## 5. Notes and Caveats

1. **Speed**  
   The nRF24L01 supports data rates of 250 kbps, 1 Mbps, or 2 Mbps under good conditions, but in practice, throughput will be lower due to overhead, retries, and collisions.

2. **Reliability**  
   Especially at longer ranges, packet loss can be non-trivial. Ensure you have a robust retry strategy (the TMRh20 library can auto-retry, and you can layer your own application-level checks as well).

3. **Security**  
   The nRF24L01 does not have built-in encryption like Wi-Fi. If you need secure file transfer, you must implement your own encryption (e.g., AES in software) before sending chunks over RF.

4. **File Size**  
   For very large files, transfer times could be significant. If performance or reliability becomes a concern, you might want to consider a more traditional solution (e.g., Wi-Fi or Ethernet).

5. **No Native Network Interface**  
   The kernel won’t see `nRF24L0` as a traditional network interface (like `eth0` or `wlan0`). There is no off-the-shelf kernel driver that makes it a socket-based interface. All file transfer logic must be at the application level or use libraries like RF24Network.

---

## Summary

Using nRF24L01 modules to transfer files between two Linux devices essentially requires you to:

1. Connect each module to your device’s SPI pins.  
2. Use a library (like TMRh20’s RF24) to configure and talk to the module.  
3. Write or adapt existing code to chunk and transmit the file data in small packets (up to 32 bytes).  
4. Implement a simple handshake/acknowledgment scheme to ensure reliability.  

While this is very doable for smaller files or constrained environments, it’s more low-level and labor-intensive than using a standard IP-based interface. Still, with the right libraries and some custom scripting, you can make it work for point-to-point file transfer over nRF24L01 radios on Linux.
